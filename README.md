## Audit Methodology

Auditrate security assessments may include:

- Manual line-by-line code review
- Architecture and business logic analysis
- Access control and privilege analysis
- Static analysis
- Targeted security testing
- Fuzz and invariant testing where applicable
- External call and reentrancy analysis
- Token and accounting logic analysis
- Economic and manipulation risk analysis
- Proof-of-concept testing for identified vulnerabilities
- Remediation verification

The exact methodology and testing scope may vary depending on the architecture and complexity of each project.

## Severity Classification

Findings are classified according to their potential impact and likelihood of exploitation:

| Severity | Description |
|----------|-------------|
| Critical | Vulnerability capable of causing catastrophic loss of assets or complete protocol compromise |
| High | Serious vulnerability with significant security or financial impact |
| Medium | Security issue that may cause meaningful impact under specific conditions |
| Low | Limited-impact security issue or implementation weakness |
| Informational | Security recommendation, code-quality observation, or best-practice improvement |

## Report Integrity

Each audit identifies the exact code or deployed smart contract reviewed.

Where applicable, reports include:

- Blockchain network
- Contract address
- Repository and commit hash
- Compiler version and configuration
- Verified source information
- Audit scope
- Report version

An audit applies only to the specific code and version identified in the corresponding report.

## Disclaimer

A security audit does not constitute a guarantee that a smart contract is free from vulnerabilities.

Auditrate assessments are limited to the scope and code identified in each report. Audits do not constitute an endorsement of a project, its team, token, business model, or investment potential.

Users and project teams remain responsible for conducting their own independent security and risk assessments.
